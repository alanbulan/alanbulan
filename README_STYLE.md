# README 风格规范

用于这个账号下的项目文档整理，参考 TuneFree 当前 README 的信息层级，不复制其产品能力或品牌资产。

[个人主页](./README.md) · [公开项目目录](./PROJECTS.md)

## 首屏

居中放真实图标（有则使用）、项目名、一句话定位、少量徽章和快速导航。统一使用 `flat-square`，可选强调色为珊瑚粉 `fb7185`、浅紫 `818cf8`、薄荷绿 `5eead4`。没有现成图标或真实截图时，宁可留白，不挂不存在的文件。

徽章只展示有依据的信息。版本徽章对应实际发布仓库，CI 徽章指向存在的工作流，许可徽章需要真实且一致的许可依据。不能把静态写出的“通过”“100%”当成自动验证结果，也不把一个项目的社区认可移植到其他项目。

## 页面顺序

| 顺序 | 内容 | 要回答的问题 |
| --- | --- | --- |
| 1 | 项目定位 | 解决什么问题，面向谁，是产品、实验、模板还是上游副本？ |
| 2 | 安装或快速开始 | 去哪里获取，用什么环境，运行哪些真实存在的命令？ |
| 3 | 能力表 | 当前有什么，依赖哪些外部条件？ |
| 4 | 架构与源码导航 | 模块如何分工，读者应该从哪里进入？ |
| 5 | 开发与验证 | 哪些脚本实际存在，哪些检查未运行？ |
| 6 | 许可、来源与限制 | 上游来自哪里，能力边界和授权范围是什么？ |

首屏保持短，深层运行时、完整发布过程和历史联调记录放入独立手册或折叠区。已有详细文档应保留，移动时检查相对链接；原文副本放在同一级目录可维持相对路径基准。

## 内容核对

技术栈从 manifest 与锁文件读取；启动命令从 scripts、构建配置或已验证入口读取。框架支持某个平台不等于该仓库已有该平台安装包。打包脚本存在、CI 成功、实机安装和业务验收是不同的事实。

数据初始化、迁移、部署与清理命令应说明副作用，不能把写入远程数据库的命令当作普通预览命令。示例中不用真实密码、令牌、客户数据或私人联系方式。

历史记录保留日期和环境，不使用没有证据的“完全正常”“生产可用”“性能极高”“全部覆盖”。README 改版本身不是新的运行验收。

## 不同仓库的处理

| 类型 | 文档原则 |
| --- | --- |
| 重点产品 | 统一首页结构，保留产品自己的图标、截图、技术栈与发布事实 |
| 领域作品 | 写清领域与工程入口，不把旧实验包装成当前生产系统 |
| 模板与试验 | 明确模板来源，不由默认 README 推断代码为空 |
| 上游副本 / Fork | 保留署名与许可，先说明本仓库关系和差异，不全部覆盖成原创品牌 |
| 私有工作区 | 保持可见性，项目名和内部详情不进入公开主页或公开审计文档 |
| 空仓库 | 在确认非代码用途之前保留；归档是管理动作，不靠文档文字冒充 |

## 变更与回滚

每次整理仅提交必要文档，保留 Git 历史。需要恢复时优先回滚对应提交或恢复单个文档，不对活跃仓库强制重置分支。自动生成的目录应区分整理前的业务推送记录与本次文档提交，避免制造活跃度假象。
